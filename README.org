#+title: Strudel for Emacs

Write and play [[https://strudel.cc/][Strudel]] in Emacs buffers and Org source blocks.
Uses embedded WebKit with a locally installed runtime and samples.
Experimental; tested on macOS with Emacs 31.1.

* Install

Requires GUI Emacs 29.1+ built with Xwidgets. No Node.js or external browser is needed.

Add this checkout to your configuration:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/strudel.el")
(require 'strudel)
(with-eval-after-load 'org (require 'ob-strudel))
#+end_src

Alternatively, run =make package= and install =dist/strudel-0.1.0.tar= with
=M-x package-install-file=. Add the Org configuration above if needed.

Run =M-x strudel-setup= once to download and verify =@strudel/web 1.3.0=.
The runtime is stored under =user-emacs-directory= in =var/strudel/runtime/1.3.0/=;
customize =strudel-runtime-directory= to change it. Playback needs no internet connection.

* Play

1. Open [[file:examples/song.org][examples/song.org]], which includes local drum samples.
2. Press =C-c C-c= inside a source block. The player starts and plays it automatically.
3. Edit and evaluate again to update playback. Use =M-x strudel-stop= to stop.

The first evaluation starts the runtime; later evaluations reuse it.
While it starts, only the latest evaluation is kept. =strudel-stop= cancels it.
Evaluating in another project switches the shared player to that project's samples.
You can still use =strudel-start= to prepare the player ahead of time.
Startup restores your editing layout and enables audio automatically.
WebKit is rendered once during startup, so the player may briefly flash.
Use =M-x strudel-show= to open its controls; =strudel-quit= closes the session.
If WebKit blocks automatic audio, the player opens for a manual *Enable audio* click.
Errors appear in =*Strudel errors*=.

Org also supports =C-c '= for editing, =:dir=, and noweb expansion.
Use =:results silent= for live playback. Named sessions, =:var=, and recording
are not supported. One shared session plays the most recently evaluated code.

For =.strudel= or =.str= files, or a JavaScript buffer with =strudel-mode= enabled:

| Key | Action |
|-----+--------|
| C-c C-c | Evaluate buffer |
| C-c C-r | Evaluate region, replacing the complete pattern |
| C-c C-s | Stop |
| C-c C-z | Start runtime |

* Samples

Place audio in =samples/= beside your file, or use =M-x strudel-import-samples=
to copy a folder there. Existing folders are never overwritten.
Restart the player with =strudel-quit= and =strudel-start= after changing samples.

Without a manifest, =kick.wav= becomes =kick=. Files in a subfolder are grouped
by that folder's name and sorted alphabetically: =drums/a.wav= and =drums/b.wav=
become =drums:0= and =drums:1=.

An optional =samples/strudel.json= defines names explicitly:

#+begin_src json
{"kick": "kick.wav", "snare": ["snare-a.wav", "snare-b.wav"]}
#+end_src

Paths must be relative to =samples/=. The player supplies the local base URL.
WAV is recommended; other formats depend on WebKit's decoders.
Samples are decoded on demand, so the first hit of a large sample may be delayed.

Assets are served on =127.0.0.1=. External resource requests are blocked;
copy remote samples locally before using them. This is a small player, not the
full online REPL: piano roll, Hydra, and recording UI are not included.

* Development

#+begin_src sh
make check
make test
make test-package
#+end_src

For the WebKit/audio check, start the example project, load
=test/strudel-webkit-smoke.el=, and run =M-x strudel-test-webkit=.
It plays briefly at low volume and stops automatically.
Read the result with =M-x strudel-test-webkit-result=.
